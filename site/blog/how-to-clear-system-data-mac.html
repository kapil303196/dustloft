How to clear System Data on a Mac safely (MacBook Air, Pro or iMac)

Guide · 10 min read · By Kapil Upadhyay at Logicspark · Published 8 September 2026 · Updated 8 November 2026

Short answer: find out what is inside System Data before deleting anything. Use du -kxd 1 to measure each folder, work from the largest item down, and never delete a .git directory, anything inside a cloud-synced folder, or a Docker volume.

Every guide that tells you to empty ~/Library/Caches is aiming at the wrong target. This one starts by measuring, because System Data is a label rather than a category and what sits behind it differs on every machine.

Before Terminal: four quick wins

Most people searching for this are not developers, and the first gigabytes are often in places macOS will clear for you:

  1. Look at Storage settings. System Settings › General › Storage lists recommendations and categories. System Data itself has no list and no delete button, which is why the rest of this guide exists.
  2. Delete old iPhone backups. Click the ⓘ next to iOS Files in the same window. Which backups are safe to delete.
  3. Remove Time Machine local snapshots if you need space right now: tmutil listlocalsnapshots / shows them. How to delete or thin them.
  4. Restart, and install any pending macOS update. A restart clears swap files, and installing the update clears the files staged in /Library/Updates, which you cannot delete by hand. Why sleepimage, swap and update files should be left alone.

If System Data is still large after that, the space is in your home folder. Measure it.

Step 1 — See where the space actually went

Open Terminal and run this. It measures every folder in your home directory in one pass:

du -kxd 1 ~ 2>/dev/null | sort -rn | head -20

The flags matter. -x stays on one filesystem so it does not wander into mounted volumes, -d 1 stops at one level deep, and -k reports in kilobytes so sort -rn orders correctly.

Repeat it one level down on whatever is largest:

du -kxd 1 ~/Library 2>/dev/null | sort -rn | head -20

A warning about the obvious command

Almost every guide online suggests du -sh ~/*. That command silently skips every hidden folder, because the shell glob * does not match names beginning with a dot. On the machine used for this guide it hid 55 GB: ~/.ollama at 16 GB, ~/.cache at 10 GB and ~/.Trash at 9.3 GB were all invisible. Use du -kxd 1 ~ instead, which includes them. The full set of measurement commands, including how to list individual files over 1 GB, is covered separately.

Step 2 — Empty the Trash properly

Check what is in it first, because deleted applications often leave root-owned files that refuse to delete normally:

du -kxd 1 ~/.Trash | sort -rn | head

If normal emptying fails, the items are owned by root and need elevation.

Step 3 — Remove leftovers from apps you uninstalled

Uninstalling never removes these. Look for folders belonging to applications you no longer have:

du -kxd 1 ~/Library/Application\ Support ~/Library/Containers 2>/dev/null | sort -rn | head -20

Folder names are reverse-DNS bundle identifiers, so com.microsoft.teams2 belongs to Teams. If the application is gone, its folder is dead weight. Leave anything starting com.apple. alone.

Step 4 — Reclaim developer space

If you write code, this is usually where the bulk is:

# Dependency folders — restored by npm install
find ~/Projects -type d -name node_modules -prune | wc -l

# Docker: removes unused images, never volumes
docker system prune -a

# Local AI models
ollama list

Docker deserves a note. docker system prune -a is safe because it never touches named volumes, which is where database data lives. Never add --volumes unless you know precisely what you are discarding. If Docker.raw stays large after a prune, sparse files explain why.

Step 5 — Check for one enormous file

mdfind -onlyin ~ "kMDItemFSSize > 1000000000" 2>/dev/null

Forgotten screen recordings, video editing scratch caches and virtual machine disks all show up here.

The .git trap specifically

A repository with a remote configured looks backed up. It is not, until something has actually been pushed. Verify before assuming:

git -C /path/to/repo ls-remote origin | wc -l

If that returns 0, the remote exists but is empty — nothing was ever pushed, and the local .git is the only copy in existence. Run git gc --prune=now to shrink it instead of deleting it.

MacBook Air, MacBook Pro or iMac: is it different?

No. System Data lives in the same places on every Mac running macOS 13 or later, so the steps above work unchanged on a MacBook Air, MacBook Pro, iMac, Mac mini or Mac Studio, on Apple silicon or Intel. What differs is how soon it matters: a 256 GB MacBook Air with 40 GB of System Data has lost about a sixth of its disk, while the same 40 GB on a 1 TB iMac goes unnoticed.

Common questions

Can you delete System Data on a Mac?

Not as one item, because System Data is a label for many unrelated files. You can delete the parts of it that are safe: caches, Time Machine local snapshots, old iPhone backups, build output and leftovers from removed apps. Never delete it wholesale.

Why can't I click System Data in Storage settings?

macOS shows System Data as a total without a list of contents and gives it no delete button. Use du -kxd 1 ~ in Terminal, or a tool such as Dustloft, to see what is inside it.

Is clearing System Data different on a MacBook Air or iMac?

No. Every Mac running macOS 13 or later stores System Data in the same places, so the same steps work on a MacBook Air, MacBook Pro, iMac, Mac mini or Mac Studio. Smaller 256 GB drives simply fill up sooner.

How do I clear System Data on my Mac?

Measure first with du -kxd 1 to find what is actually inside it, then work from the largest item down. Caches, build output and unused Docker images are safe. App containers, device backups and .git directories are not.

Does deleting System Data speed up a Mac?

Not directly. It frees disk space. macOS does slow down when a disk is nearly full, so reclaiming space on a drive above 90% full often helps indirectly.

Why does du -sh miss folders on Mac?

The shell glob does not match names starting with a dot, so hidden folders such as ~/.cache and ~/.Trash are skipped entirely. Use du -kxd 1 ~ instead.
